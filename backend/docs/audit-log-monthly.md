# 登录与操作日志月表

物理表为 `sys_login_log_YYYYMM`、`sys_operation_log_YYYYMM`；`sys_log_month` 统一登记登录、操作、HTTP 日志的类型、月份和结构版本，联合主键为 `(kind, month)`。月表不参与 ORM 自动迁移，旧单表仅作为迁移源和备份。

当前部署使用独立 `logs` 数据源（开发库为 `res-nexus-log`）。日志接口、后台写入、月表创建和保留期清理均走日志库，配置和跨库搬迁顺序见 [多数据源说明](multiple-databases.md)。

月份按北京时间的事件发生时间计算；数据库时间保持 UTC（历史无时区时间按 UTC 解释）。API 时间范围使用北京时间 YYYY-MM-DD HH:mm:ss，入参转 UTC 后查询；月份边界对应 UTC 上月最后一天 16:00 至本月最后一天 16:00，右边界不包含。

## 升级现有环境

迁移命令仅将 **logs 数据源内已有的旧单表** 拆成月表，不承担跨库搬迁。拆库前应先完成旧版本历史迁移，再按多数据源说明搬迁已有日志表及目录；不要在拆分后的主库重放历史日志建表迁移。

1. 停止全部后端实例、任务及其他日志写入者，并备份数据库。
2. 在 `backend` 目录执行 `uv run main.py upgrade --env=dev`（生产用 `--env=prod`）。
3. 执行 `uv run main.py migrate-audit-logs --env=dev --batch-size=1000`。
4. 确认输出各类型 `verified`、月份数量符合旧表；迁移会逐字段校验、校验月表总数，并修复 PostgreSQL 自增序列。重复执行时已存在且完全一致的记录跳过；ID/UUID 冲突或数量不一致则中止，不覆盖记录。失败前已提交的批次可安全重跑。
5. 启动后端并部署新版管理前端。原单表保留，不自动删除，不再用于日常查询或写入。

迁移期间不得启用新日志写入。新月表已存在额外记录时，计数校验会中止，应先核对，不能删除记录强行通过。SQLite/MySQL 显式插入历史 ID 会自动推进自增值；PostgreSQL 由迁移命令执行 `setval`。

## API

原 `/system/log/login` 和 `/system/log/operation` 下的列表、详情、删除、操作日志导出接口增加必填查询参数 `month=YYYYMM`。原请求体、响应信封与权限标识保持不变；旧客户端必须同步升级。

新增 `GET /system/log/login/months`、`GET /system/log/operation/months`，返回登记月份的倒序列表，使用原查询权限。合法的无数据月份返回空列表；查询不会建表。详情和删除必须携带记录所属月份，三类日志的 `id` 均为 `VARCHAR(32)` 字符串主键，新记录生成无连字符的 UUID；详情、删除和批量选择均使用字符串 ID。

启动时建当前月与下个月，历史延迟写入按发生月份补建。SQLite 使用写事务锁，MySQL 使用 GET_LOCK，PostgreSQL 使用事务 advisory lock。登录/操作日志写入失败沿用现有只记录应用日志、不影响业务的方式。

清理任务 `cleanup_expired_logs(days=90)` 保持调用和返回统计兼容：整月过期时删月表及登记，临界月份按 UTC 截止时间逐条物理删除。该任务不会处理保留为备份的旧单表。

登录、操作日志月表结构版本为 2，HTTP 日志保持版本 1。以后修改字段时，必须新增显式迁移处理已登记月表及模板，不能只修改 ORM 旧表模型；不支持的版本会拒绝写入。自动降级遇到已登记月表会中止，以保留审计数据。

内置清理任务使用 `builtin:audit_log_cleanup` 白名单处理器，无需开启代码块执行。迁移仅替换 `code=log_cleanup` 且函数内容仍等于原始种子代码的任务；自定义任务函数保持不变，需自行接入该处理器。执行器、03:00 调度、状态和 kwargs.days 保持原配置。工作线程使用独立的 NullPool 引擎，避免跨事件循环复用数据库连接。

统一目录中的 `kind` 为 `login`、`operation`、`http`。月份查询始终按类型筛选；审计清理只处理 `login` 和 `operation`，不处理 HTTP 日志。旧迁移保留旧目录定义兼容入口，运行时不创建或读取旧目录表。


## 字符串主键、整合页签与本地时间

登录/操作日志旧单表及月表升级为 `VARCHAR(32)` 主键。先停写，再执行 `uv run main.py upgrade-log-ids --env=dev`；应用启动也会执行相同幂等检查。迁移从已有 UUID 派生 32 位 ID，在影子表逐字段核验后替换，拒绝重复 UUID、外键及未处理的中间表。旧整数详情地址不再适用；历史日志字段与记录数保持不变。HTTP 日志原本即使用 `VARCHAR(32)`，无需改写 ID。

HTTP 调用日志作为日志管理第三个页签，沿用原查询/详情/正文/下载权限；旧独立菜单转换为权限节点。只有 HTTP 权限的角色不会获得其他日志的查询权限。

列表默认按事件时间倒序，ID 倒序仅用于相同时间时稳定分页。三类日志接入框架统一北京时间契约：接口输出和筛选入参均为 YYYY-MM-DD HH:mm:ss。HTTP 历史值保留北京时间存储语义，登录/操作日志保留 UTC 存储。页面不依赖浏览器时区。详见 datetime-contract.md。
